# Посібник користувача (1С)

Документ показує типові сценарії з боку 1С:Підприємства. Повний перелік методів
і властивостей — [component-methods.md](component-methods.md); коди помилок —
[error-codes.md](error-codes.md).

## Підключення компоненти

```bsl
ПодключитьВнешнююКомпоненту(ПутьКDll, "Tamga", ТипВнешнейКомпоненты.Native);
Компонента = Новый("AddIn.Tamga.Tamga");
```

Розрядність `Tamga.dll` має збігатися з розрядністю платформи 1С: 32-бітний
тонкий клієнт не завантажить 64-бітну компоненту.

Усі методи мають англійські та російські імена. Нижче використано російські —
вони звичніші в 1С-конфігураціях; англійські еквіваленти працюють так само.

## Життєвий цикл сесії

```bsl
Компонента.Инициализировать();

// ... робота ...

Компонента.ЗавершитьРаботу();
```

`Инициализировать()` застосовує типові налаштування. Історична властивість
`НеобходимоУстановитьПараметры` збережена для сумісності, але будувати навколо
неї нову логіку не потрібно.

## Налаштування

```bsl
// Загальні: автономний режим, робочий каталог, режим довіри, глибина валідації
Компонента.Настроить(Ложь, "C:\Tamga\work", "strict", "standard", Ложь);

// Служба міток часу
Компонента.НастроитьTSP("http://acskidd.gov.ua/services/tsp/", , 10000);

// OCSP
Компонента.НастроитьOCSP("http://acskidd.gov.ua/services/ocsp/", Истина, 10000);

// Довірчий список ЦЗО
Компонента.НастроитьДоверенныйСписок("https://czo.gov.ua/download/tl/TL-UA.xml", 30000, 24);
Компонента.ОбновитьДоверенныйСписок();
```

Без аргументів `Настроить()` використовує безпечний типовий режим
`offline=true`. Автономний режим (`Настроить(Истина, ...)`) вимикає всі
мережеві звернення: TSP, OCSP, AIA і синхронізацію довірчого списку.
Online-режим вмикається лише явно через перший аргумент `Ложь`.

П'ятий аргумент окремо дозволяє AIA-завантаження проміжних сертифікатів за URL
із сертифіката. Його типове значення `Ложь`; для opt-in передайте `Истина`, але
лише разом з `offline=false`. HTTP-клієнт у будь-якому разі відхиляє loopback,
приватні, link-local, metadata та інші non-public адреси, включно з redirect-ами.

## Завантаження ключа

```bsl
// З файлу
Компонента.ЗагрузитьКлюч(ПутьКФайлу, ПарольКонтейнера);

// З двійкових даних, із явним типом джерела
Компонента.ЗагрузитьКлюч(ДвоичныеДанные, ПарольКонтейнера, "", "", "jks");
```

Підтримуються контейнери PKCS#12 (`.pfx`, `.p12`, `.dat`) і Java KeyStore
(`.jks`). Тип визначається автоматично; параметр `sourceType` потрібен, лише
коли автовизначення помиляється.

Після завантаження властивість `ЛичныйКлючСчитан` стає істинною.

## Підпис даних

```bsl
// Відокремлений CMS (типово)
Подпись = Компонента.ПодписатьДанные(ДвоичныеДанные);

// Приєднаний CMS у Base64
Подпись = Компонента.ПодписатьДанные(ДвоичныеДанные, "cms-attached", "base64");
```

Формати для `ПодписатьДанные`/`ПроверитьПодпись` — тільки CMS/CAdES:
`cms-detached`, `cms-attached`, `cades-bes`, `cades-t`. Контейнерні й XML/PDF
значення (`asic-s`, `asic-e`, `xades`, `pades`, `asic-e-xades`) ці два методи
відхиляють у **будь-якій** конфігурації збірки, повертаючи `Ложь`
(`TamgaAddIn.cpp:505` і `:584`): вони працюють із файлами, а не з блобом.
Контейнери підписуються через `ПодписатьФайл`, XML — через `ПодписатьXML`,
PDF — через `ПодписатьPDF`. Що саме кожен метод уміє підписати проти того, що
вміє перевірити, зведено в [component-methods.md](component-methods.md),
розділ «Аргумент `signatureFormat` асиметричний: підпис ≠ перевірка».

## Підпис файлів, XML і PDF

```bsl
// ASiC вимагає ЧЕТВЕРТОГО аргументу "file": з типовим "binary"
// ПодписатьФайл поверне Ложь, не створивши контейнера.
Компонента.ПодписатьФайл(Вхідний, Вихідний, "asic-e", "file");

ПодписанныйXML = Компонента.ПодписатьXML(ИсходныйXML, "xades-t");

ПодписанныйPDF = Компонента.ПодписатьPDF(ДвоичныеДанныеPDF);
```

`ДвоичныеДанныеPDF` мають містити повний незашифрований PDF, що починається з
`%PDF-`. `ПодписатьPDF` додає PAdES як incremental update: оригінальний файл,
його AcroForm-поля та попередні підписи не переписуються. Довільні байти або
зашифрований PDF метод відхиляє з помилкою.

## Перевірка

```bsl
Результат = Компонента.ПроверитьПодпись(ДвоичныеДанные, Подпись);

Если Не Результат Тогда
    Сообщить(Компонента.ПолучитьОшибку());
КонецЕсли;

ТехническийОтчет = Компонента.ПолучитьОтчет();          // JSON для програмної обробки
ОтчетПользователя = Компонента.ПолучитьОтчетПользователя(); // JSON для показу людині
```

### Як читати результат

Це найважливіше місце документа.

`ПроверитьПодпись` повертає **істину, якщо криптографічна цілісність підпису
підтверджена**. Це ще не означає, що підпис юридично дійсний.

Для юридично значущого рішення читайте звіт і дивіться окремі розділи:

| Розділ звіту | Що означає |
| --- | --- |
| `signature` | Криптографічна цілісність |
| `certificate` | Чинність сертифіката на момент валідації |
| `trust` | Чи побудовано ланцюг до довіреного якоря з довірчого списку ЦЗО |
| `revocation` | Чи перевірено відкликання (OCSP/CRL) і з яким результатом |
| `timestamp` | Стан мітки часу |
| `summary` | Зведений вердикт із кодом |

Типова ситуація без налаштованого довірчого списку: `signature.status = valid`,
але `trust.status = invalid` і `summary.code =
SIGNATURE_INTEGRITY_ONLY`. Це коректна відповідь «підпис цілісний, довіра не
підтверджена», а не помилка.

**Але не всяка невдача політики — попередження.** `SIGNATURE_INTEGRITY_ONLY`
означає саме «перевірити не було чим»: немає довірчого списку, ланцюг не
добудувався, сервіс OCSP не відповів. Якщо ж перевірка **виконалась і
відхилила** підпис, `summary.status` буде `invalid` з конкретною причиною:

| `summary.code` | Що сталося |
| --- | --- |
| `CERTIFICATE_REVOKED` | Сертифікат підписувача **відкликано** |
| `CERTIFICATE_INVALID_AT_VALIDATION_TIME` | Сертифікат недійсний на час перевірки |
| `REVOCATION_INVALID` | Дані про відкликання (OCSP/CRL) некоректні |
| `TIMESTAMP_INVALID` | Мітку часу відхилено |
| `CONTAINER_COVERAGE_INCOMPLETE` | Частина документа не покрита підписом |
| `CONTAINER_MALFORMED` | Структура контейнера пошкоджена: маніфест посилається на відсутній обʼєкт або імена записів неоднозначні. Повторювати перевірку немає сенсу — потрібен новий примірник від відправника |
| `SIGNATURE_INVALID` | Криптографічну цілісність не підтверджено |

До 2026-08-29 усі ці випадки, крім двох останніх, поверталися як
`warning`/`SIGNATURE_INTEGRITY_ONLY` — тобто відкликаний сертифікат був
нерозрізнимий від ненаcтроєного довірчого списку. Якщо ваша конфігурація
покладалася на те, що `summary.status` ніколи не буває `invalid` через
політику, її треба переглянути: **це і був дефект**, а не поведінка, на яку
можна спиратися.

## Зовнішні сервіси: незалежна перевірка і пошук сертифіката

Корисно мати друге, незалежне від Tamga джерело правди — і коли треба
переконатися, що створений підпис приймають сторонні системи, і коли до ключа
бракує сертифіката.

| Що потрібно | Сервіс |
| --- | --- |
| Перевірити підписаний файл | `https://ca.diia.gov.ua/verify` |
| Знайти і **завантажити** сертифікат | `https://ca.diia.gov.ua/certificates-search` |
| Те саме, альтернативний сервіс | `https://acsk.privatbank.ua/online-services` |

Пошук у Дії працює за ЄДРПОУ, РНОКПП або реєстраційним номером сертифіката й
охоплює всі КНЕДП, а не лише одного надавача — тому саме він найшвидше дає
`.cer` до контейнера, у якому сертифіката немає (`.dat`, `Key-6.dat`, `.ZS2`).
Завантажений файл достатньо покласти поруч із ключем під тим самим іменем
(`ключ.dat` → `ключ.cer`), і Tamga підхопить його без додаткових налаштувань —
див. [key-containers.md](key-containers.md).

Обидва сервіси розраховані на людину: форма пошуку в Дії захищена CAPTCHA, а
сторінка ПриватБанку працює лише з увімкненим JavaScript. Автоматизувати їх з
коду не можна — це ручний крок.

Перевірено 2026-09-03: усі три адреси відповідають HTTP 200.

## Обробка помилок

```bsl
Если Не Компонента.ЗагрузитьКлюч(Путь, Пароль) Тогда
    Сообщить("Не вдалося завантажити ключ: " + Компонента.ПолучитьОшибку());
    Возврат;
КонецЕсли;
```

Метод повертає `Ложь`, якщо **операція не виконалась**. Якщо операція
виконалась, але підпис виявився невалідним, `ПроверитьПодпись` теж поверне
`Ложь` — розрізнити ці випадки можна за звітом: у другому
`diagnostics.flags.executionSucceeded` буде істинним.

Перелік кодів — [error-codes.md](error-codes.md).

## Обмеження

- `ПоказатьСертификаты` і `ПоказатьСпискиОтзыва` можуть повертати
  `GuiNotAvailable`: графічний інтерфейс належить до наступних фаз.
- LDAP і CMP реалізовані частково; перевіряйте коди NotSupported та результат конкретної операції.
- У збірці з `TAMGA_ENABLE_VENDOR_CRYPTONITE=OFF` методи підпису й перевірки
  повертають `NotSupported`. Це діагностичний режим, а не робоча конфігурація.
