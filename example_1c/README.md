# Приклади 1С для Tamga

Каталог містить тільки приклади, що належать до поточного проєкту Tamga.

## Склад

| Файл або каталог | Призначення |
| --- | --- |
| `TamgaSignFile.xml` | Прикладна обробка «Підписання файла»: один сценарій, двомовний інтерфейс. |
| `TamgaSignFile/` | XML-вивантаження цієї обробки; binary-макети додаються зі збірки. |
| `TamgaUIv2.xml` | Основний приклад зовнішньої обробки для V2 NativeAPI. |
| `TamgaUIv2/` | XML-вивантаження обробки з формою підпису. |
| `TamgaUI.xml` | Легкий метаопис попереднього Tamga UI-прикладу, залишений як Tamga-артефакт. |
| `TamgaDemo.xml` | Легкий метаопис demo-прикладу, залишений як Tamga-артефакт. |

Застарілі приклади і тестові чернетки вилучені.

## TamgaSignFile — обробка «Підписання файла»

Робоча обробка з одним сценарієм: вибрати файл, вибрати ключ, ввести пароль,
вибрати формат, натиснути «Підписати». Підписаний файл лягає **в той самий
каталог**, що й вихідний.

### Склад форми

| Елемент | Призначення |
| --- | --- |
| `Вибраний файл` | Діалог вибору файла, який підписуємо. |
| `Ключ КЕП (ЕЦП)` | Діалог вибору контейнера ключа (`*.dat`, `*.zs2`, `*.jks`, `*.pfx`, `*.p12`, `*.pem`, `*.der`). |
| `Пароль` | Пароль контейнера; поле в режимі пароля. |
| `Формат підпису` | Випадний список: `cms-detached`, `cades-bes`, `cades-t`, `asic-s`, `asic-e`. |
| `Підписати` | Виконує весь ланцюжок: підключення → налаштування → `ЗагрузитьКлюч` → `ПодписатьФайл`. |
| `Результат` | Шлях створеного файла або текст помилки. |

### Ім'я результату

До повного імені вихідного файла додається розширення формату:
`invoice.pdf` → `invoice.pdf.p7s` (`.asics` для ASiC-S, `.asice` для ASiC-E).
Якщо таке ім'я вже зайняте, додається лічильник — `invoice.pdf (1).p7s`.
Наявні підписи не перезаписуються.

### Компонента

Кожна розрядність — окремий макет із «голою» `Tamga.dll`, без ZIP-бандла й
`MANIFEST.XML`:

| Макет | Вміст |
| --- | --- |
| `TamgaWindowsX86` | `Tamga.dll`, Windows x86 |
| `TamgaWindowsX64` | `Tamga.dll`, Windows x86_64 |

Потрібний макет обирає `СистемнаяИнформация.ТипПлатформы` — розрядність
**клієнтського** процесу, бо саме він завантажує native-бібліотеку. Далі два
кроки: спершу підключення прямо з макета
(`"ВнешняяОбработка.TamgaSignFile.Макет.TamgaWindowsX64"`), а якщо платформа
його не прийняла — макет вивантажується у `%TEMP%\Tamga1C\Tamga-windows-x64.dll`
і компонента підключається за повним шляхом. Другий крок потребує серверного
виклику `ПолучитьМакет`, тому у форми є основний реквізит `Объект`.

Оновити компоненту після перезбірки — просте копіювання, пакувати нічого не
треба:

```powershell
Copy-Item build-portable-x86/Tamga.dll example_1c/TamgaSignFile/Templates/TamgaWindowsX86/Ext/Template.bin -Force
Copy-Item build-portable-x64/Tamga.dll example_1c/TamgaSignFile/Templates/TamgaWindowsX64/Ext/Template.bin -Force
```

Linux/macOS у макетах немає: постачання компоненти для цієї обробки —
Windows-only, і на іншій платформі обробка каже це прямо, а не мовчки падає.

### Збірка `.epf` із цього вивантаження

```
1cv8 DESIGNER /F <база> /LoadExternalDataProcessorOrReportFromFiles example_1c/TamgaSignFile.xml TamgaSignFile.epf
```

Той самий крок доступний у Конфігураторі командою завантаження зовнішньої
обробки з файлів (8.3.11+) та імпортом у 1C:EDT.

### Що обробка робить, а що ні

- `cades-t` вмикає онлайн-режим і запитує мітку часу в TSA. Адреса TSA не
  задається на формі: передається порожній URL, і компонента бере адресу з
  довірчого списку ЦЗО або з таблиці відомих КНЕДП за issuer'ом сертифіката.
  Для production задавайте адресу явно через `НастроитьTSP`.
- Решта форматів підписується в офлайн-режимі, без жодного мережевого виклику.
- Без сертифіката підпис неможливий у принципі: якщо його немає ні в контейнері,
  ні поруч, ні в мережі, підписання відмовить із
  `Loaded key container does not include signer certificate`.
- **Формати ключів, які працюють з 0.7.0**: `.jks`, `.pfx`/`.p12`, `.pem`/`.der`,
  `.dat` як PKCS#12 (Вчасно/ДПС), **власний контейнер ІІТ** `Key-6.dat` і
  **`.ZS2`** ЦСК «Україна». Два останні раніше відмовляли (`rc=102` і `rc=536`).
  Розпізнавання йде за вмістом, тому розширення ні на що не впливає — деталі й
  точні OID у [docs/key-containers.md](../docs/key-containers.md).
- **Контейнери без сертифіката** (`.dat`, `Key-6.dat`, `.ZS2` — сертифіката
  всередині немає у жодного) підписують, якщо сертифікат лежить поруч із ключем
  під тим самим іменем (`ключ.dat` → `ключ.cer`) або переданий явно.
- **«Універсальний» контейнер із двома ключами**: береться той ключ, що
  відповідає сертифікату підписанта. Сертифікатом ключа протоколів розподілу
  ключів підписати не можна — гейт `keyUsage` відмовить із поясненням.
- `cms-attached` у списку немає навмисно: `ПодписатьФайл` відхиляє його в
  будь-якому кодуванні. Перевірки підпису ця обробка не робить — для неї є
  `TamgaUIv2`, а незалежно перевірити готовий файл можна на
  `https://ca.diia.gov.ua/verify`.
- Якщо до ключа бракує сертифіката, його шукають і завантажують на
  `https://ca.diia.gov.ua/certificates-search` (за ЄДРПОУ, РНОКПП або
  реєстраційним номером, по всіх КНЕДП) або на
  `https://acsk.privatbank.ua/online-services`. Завантажений `.cer` кладуть
  поруч із ключем під тим самим іменем — і обробка підхопить його сама.
- Двомовність: заголовки елементів форми задані мовними рядками метаданих
  (`uk` + `ru`), рядки з коду — через `НСтр`. Обгортка `Локализовать()` бере
  мову сеансу, а якщо її в шаблоні немає — послідовно `uk` і `ru`, тож у
  конфігурації з третьою мовою інтерфейсу текст не зникає.
- Модуль форми лежить у `Forms/ФормаПодписи/Ext/Form/Module.bsl`. Саме цей
  шлях читає Конфігуратор під час «Загрузить из файлов»; код у
  `Forms/ФормаПодписи/Ext/Module.bsl` мовчки ігнорується, і форма
  завантажується з порожнім модулем.

## Базовий V2 workflow

```bsl
Если Не ПодключитьВнешнююКомпоненту("C:\Tamga\Tamga.dll", "Tamga",
        ТипВнешнейКомпоненты.Native) Тогда
    ВызватьИсключение "Не удалось подключить Tamga.dll";
КонецЕсли;

Компонента = Новый("AddIn.Tamga.Tamga");

Если Не Компонента.Настроить(Истина, "C:\Tamga\work") Тогда
    ВызватьИсключение Компонента.ПолучитьОшибку();
КонецЕсли;

Если Не Компонента.НастроитьДоверенныйСписок("", 30000, 24, "", "") Тогда
    ВызватьИсключение Компонента.ПолучитьОшибку();
КонецЕсли;

Если Не Компонента.Инициализировать() Тогда
    ВызватьИсключение Компонента.ПолучитьОшибку();
КонецЕсли;

// Без синхронізації trust-store порожній, і перевірка лишається перевіркою
// криптографічної цілісності, а не довіри. В offline-режимі викликати не треба:
// метод свідомо поверне Ложь і OnlineServiceUnavailable, не чіпаючи мережу.
Если Не Компонента.ОбновитьДоверенныйСписок() Тогда
    Сообщить("Довірчий список не оновлено: " + Компонента.ПолучитьОшибку());
КонецЕсли;

Если Не Компонента.ЗагрузитьКлюч("C:\Tamga\keys\client.pfx", "password", "", "", "file") Тогда
    ВызватьИсключение Компонента.ПолучитьОшибку();
КонецЕсли;

Если Не Компонента.ПодписатьФайл(
        "C:\Tamga\data\document.pdf",
        "C:\Tamga\data\document.pdf.sig",
        "cms-detached",
        "file") Тогда
    ВызватьИсключение Компонента.ПолучитьОшибку();
КонецЕсли;

Если Не Компонента.ПроверитьПодписьФайла(
        "C:\Tamga\data\document.pdf",
        "C:\Tamga\data\document.pdf.sig",
        "cms-detached",
        "file") Тогда
    Сообщить("Перевірка не пройдена: " + Компонента.ПолучитьОшибку());
КонецЕсли;

// ПолучитьОтчетПользователя() — для показу користувачу,
// ПолучитьОтчет() — технічна діагностика. Це різні звіти, не синоніми.
Сообщить(Компонента.ПолучитьОтчетПользователя());
Сообщить(Компонента.ПолучитьОтчет());
```

## Важливо

`VerifyData` і `VerifyFile` перевіряють криптографічну цілісність CMS/ASiC та
доступні embedded chain/time ознаки. Це **не** повна trust-validation: щоб
перевірка спиралася на довірчий список ЦЗО, потрібні `НастроитьДоверенныйСписок`
до `Инициализировать` і `ОбновитьДоверенныйСписок` після нього. Без них
trust-store порожній.

Приклад `TamgaUIv2` виконує обидва виклики під час ініціалізації і показує
обидва звіти — користувацький і технічний.

## Підготовка binary-макетів

У Git зберігаються XML/BSL джерела. Перед завантаженням у Конфігуратор створіть каталоги `TamgaSignFile/Templates/TamgaWindowsX86/Ext` і `TamgaSignFile/Templates/TamgaWindowsX64/Ext`; покладіть відповідні зібрані DLL як `Template.bin`. Для `TamgaUIv2/Templates/TamgaUI/Ext/Template.bin` потрібен ZIP NativeAPI з MANIFEST.XML, який створює `scripts/pack-addon.ps1`. Потім завантажте обробку з XML та збережіть EPF. Binary-макети й EPF є локальними артефактами збірки.

Джерела форм можна перевіряти як XML; фактичне складання та відкриття форми потребує встановленої платформи 1С/BAS. Успішний CTest не перевіряє Designer.
